# Executable release review — 0.1.0

Reviewed and verified locally on 2026-10-04. Four Next.js portals, the NestJS API, three worker processes, PostgreSQL, Temporal, NATS, private S3-compatible storage and ClamAV are running. This is an implemented initial release with production container/deployment artifacts and a working sandbox. It is not a certified live insurance service or completion of every module in the architecture blueprint.

## Review fixes

| Area | Corrected behavior and evidence |
|---|---|
| Independent approval | Product publication, claims and settlement approvals compare canonical people, including additional accounts belonging to the same person. Runtime checks and database triggers reject self approval. |
| Tenant and customer ownership | Forced RLS, worker/API role separation and composite ownership foreign keys protect claims, documents, complaints, quotes, policies and operations. API containers no longer receive worker or migration database credentials. |
| Concurrent updates | Underwriting, purchase, endorsement and claim decision requests require the current `If-Match` version; missing or stale versions fail without changing state. |
| Money and contract history | Integer minor units, bounded values, unique coverage codes and deductible/limit checks avoid floating point and overflow. Published contracts retain their product, coverage, terms and monetary snapshots. Renewals use current publication metadata and reject a changed currency until a fresh quote supplies risk values in that currency. |
| Purchase and compensation | Stable effect keys, evidence queries and workflow checkpoints reconcile lost provider responses. A verified carrier decline after capture creates a verified refund and balanced accounting exactly once. |
| Claims and accounting | Historical coverage, deductible and remaining policy limits govern assessments. Separate people propose and approve payment or decline decisions. Declines retain both reasons and create no payable obligation. Ledger journals reject imbalance, late postings and mutation. |
| Identity | Password verification uses asynchronous scrypt; normalized emails are unique; production staff MFA rejects TOTP replay atomically. Sessions and mutations enforce cookie/origin controls and bounded login attempts. |
| Provider requests and webhooks | Approved public HTTPS addresses are resolved and pinned, including IPv6 checks. Response size and deadlines are bounded. Disabled actors cannot initiate a new effect; existing effects can still be reconciled. |
| Claim evidence | Upload size/type checks precede quarantine. Only scanner workers can change scan state. Real ClamAV rejects EICAR. Production checks the signature date before scanning and during readiness; stale, malformed or unavailable version responses keep documents quarantined. Clean downloads verify a pinned S3 object version and content hash. |
| Workers and startup | Dispatch no longer starves behind already started operations. Outbox and operation phases recover independently. Pool error handlers and connection bounds protect worker processes. Storage initialization retries transient failures, creates a missing bucket only on a confirmed 404 and verifies versioning. |
| Release runtime | Pinned Node/runtime libraries replace unnecessary shell/package-manager/npm contents. JSON execution health checks work without a shell. Applications run as UID/GID 65532 with read-only filesystems. The production operator job holds privileged migration credentials separately. Production service connections require verified TLS. |
| Recovery | Authenticated streaming backup/restore requires at least 32 random key bytes. Restore authenticates before creating a new database. Child-process/pipeline failures are handled; helpers support an explicit Compose project and no longer require RTK inside their implementation. |

## Additional implementation

- Customer policy complaints, versioned staff transitions, acknowledgement, investigation, resolution, customer appeal, reopened investigation and accepted closure are implemented in the API and customer/admin portals. The immutable timeline retains every reason and response.
- Configurable operational complaint targets, overdue detection and service reporting are implemented. These targets do not imply statutory compliance.
- Private in-app notifications are materialized from durable outbox events with deduplication, ownership controls and restricted read receipts. The header count reflects unread entries in the most recent 100 returned notifications.
- Claims support independently approved decline decisions in addition to the existing approval and payout workflow.
- Release CI includes the new renewal, readiness and encrypted recovery regressions. The CI definition is configured; it has not been executed on a remote runner in this session.

ClamAV's local update daemon reported a CDN cooldown through 2026-10-05 11:01:10 UTC; the cached signatures were usable for sandbox EICAR checks. Production now fails closed when signature dates exceed `CLAMAV_MAX_SIGNATURE_AGE_HOURS` (default 72, configurable from 1 to 168). Managed scanners must use UTC and enable the [VERSION protocol command](https://docs.clamav.net/manual/Usage/ClamdProtocol.html). A live deployment must provide an approved update path; cached sandbox signatures are not sufficient for activation. The observed startup delay is consistent with loading a signature engine; [official ClamAV Docker guidance](https://docs.clamav.net/manual/Installing/Docker.html) explains its memory and reload requirements.

The requested `codebase-memory` skill was installed and read, but its graph tools were not exposed in this tool session. Known source paths and executable checks were used; no graph-backed structural coverage is claimed. Frontend QA used real Chrome, screenshots and the available delegated frontend agent; no separate-provider design evaluation is claimed.

Automatic approval review rejected the Docker Scout private-image scan because it could upload private image metadata. The final scans used the safe alternative: pinned Trivy with public database downloads separated from network-disabled private archive scans.
